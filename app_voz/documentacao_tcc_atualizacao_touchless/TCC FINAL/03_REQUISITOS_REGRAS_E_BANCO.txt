PARTE B: REQUISITOS NÃO FUNCIONAIS ATUALIZADOS (RNF01-RNF12)
================================================================================

RNF01 — DESEMPENHO
Descrição: O sistema deve apresentar tempo de resposta inferior a 2 segundos
para comandos simples de navegação e controle.

RNF02 — USABILIDADE
Descrição: O sistema deve possuir interface simples, intuitiva e acessível,
com interação primária por voz.

RNF03 — COMPATIBILIDADE
Descrição: O sistema deve ser compatível com dispositivos Android versão 8 ou superior.

RNF04 — ESTABILIDADE
Descrição: O sistema deve garantir estabilidade durante o uso, sem travamentos
ou encerramento inesperado.

RNF05 — EFICIÊNCIA DE RECURSOS
Descrição: O sistema deve consumir poucos recursos do dispositivo (CPU, memória,
bateria) durante a escuta de voz.

RNF06 — DISPONIBILIDADE OFFLINE
Descrição: O sistema deve funcionar parcialmente offline, com todas as
funcionalidades principais disponíveis sem internet, exceto Google Sign-In.

RNF07 — INTEGRIDADE DE DADOS
Descrição: O sistema deve garantir a integridade dos dados armazenados no banco
SQLite, utilizando chaves estrangeiras e constraints.

RNF08 — MANUTENIBILIDADE
Descrição: O sistema deve ser de fácil manutenção e atualização, com banco de
dados versionado via migrations incrementais.

RNF09 — ACESSIBILIDADE POR VOZ
Descrição: O sistema deve permitir que o usuário realize as principais ações
sem nenhuma interação manual, apenas por comandos de voz.

RNF10 — SEGURANÇA LOCAL
Descrição: O sistema deve armazenar senhas com hash e salt, sem transmiti-las
em texto simples. Contas Google não armazenam senha local.

RNF11 — PRIVACIDADE
Descrição: O sistema não deve enviar dados de áudio ou de uso para servidores
externos, exceto os metadados de autenticação necessários ao Google Sign-In.

RNF12 — CONFIABILIDADE DA ESCUTA
Descrição: O sistema deve recuperar automaticamente a escuta de voz após erros
de reconhecimento, sem exigir reinicialização manual pelo usuário.

PARTE C: REGRAS DE NEGÓCIO (RN01-RN10)
================================================================================

RN01 — COMANDOS GLOBAIS SEMPRE DISPONÍVEIS
Descrição: Os comandos de navegação global ("meus projetos", "minhas gravações",
"dashboard", "histórico", "configurações", "voltar", "sair", "ajuda") estão
disponíveis em todas as telas, independentemente do contexto.
Exceção: Quando um modal crítico estiver aberto ou durante gravação ativa.

RN02 — PRIORIDADE DE COMANDOS
Descrição: A ordem de prioridade de processamento de comandos é:
(1) Modal crítico aberto (bloqueia tudo),
(2) Modo guiado ativo (aguarda entrada específica),
(3) Ajuda contextual aberta (aceita apenas fechar),
(4) Segurança de gravação ativa (protege operação em andamento),
(5) Comandos locais da tela,
(6) Comandos globais de navegação,
(7) Comandos personalizados do usuário,
(8) Fala não reconhecida (feedback ao usuário).

RN03 — GRAVAÇÃO NO EDITOR
Descrição: Apenas uma gravação pode estar ativa por vez. A escuta de comandos
de voz é suspensa durante a gravação (estado recordingLocked) para evitar
conflito de microfone.

RN04 — PARADA AUTOMÁTICA POR SILÊNCIO
Descrição: A parada automática por silêncio só é ativada durante gravação ativa.
O sistema monitora o nível de amplitude (dB). Se o nível permanecer abaixo do
limiar configurado (padrão -30 dB) continuamente pelo tempo configurado
(padrão 3 segundos), a gravação é encerrada automaticamente.

RN05 — ÍNDICE VISUAL EM MINHAS GRAVAÇÕES
Descrição: O índice visual (Item 1, Item 2...) é atribuído dinamicamente pela
posição na lista, não é salvo no banco. Um comando de voz que usa "item N"
é resolvido para a gravação correspondente pela posição na lista exibida.

RN06 — COMANDO PERSONALIZADO NÃO SUBSTITUI ESSENCIAL
Descrição: Uma frase personalizada não pode ser igual ou muito similar a um
comando essencial do sistema. O sistema valida o conflito antes de salvar.
Se houver conflito, o cadastro é bloqueado.

RN07 — TEMA PADRÃO ESCURO
Descrição: O tema escuro é o padrão para novas instalações (tema_escuro = 1
em configuracao_app). A preferência do usuário é preservada entre sessões.

RN08 — PREFERÊNCIA SALVA NO BANCO
Descrição: Todas as preferências do usuário (controle por voz, escuta contínua,
feedback sonoro, parada por silêncio, tempo, limiar, tema) são salvas na
tabela configuracao_app e persistem entre sessões e reinicializações.

RN09 — CONTA GOOGLE NÃO CONFUNDE COM CONTA LOCAL
Descrição: Um usuário que se autentica via Google e um usuário local com o
mesmo e-mail são tratados como contas diferentes se auth_provider diferir.
O campo auth_provider identifica o tipo de autenticação.

RN10 — LOGOUT ENCERRA ESCUTA DE VOZ
Descrição: Ao realizar logout (manual ou por voz), o sistema encerra a
sessão de escuta de voz, limpa a sessão do usuário e retorna à tela de Login.

PARTE E: SCRIPT SQL COMPLETO ATUALIZADO (BANCO VERSÃO 10)

Este é o script SQL que representa o banco de dados atual.
Substituir o script do Capítulo 9 (seção SCRIPT DE CRIAÇÃO DO BANCO DE DADOS).

-- ============================================================
-- TOUCHLESS - BANCO DE DADOS SQLite - VERSÃO 10
-- ============================================================

CREATE TABLE usuario (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    nome TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE,
    senha_hash TEXT NOT NULL,
    senha_salt TEXT,
    senha_algoritmo TEXT NOT NULL DEFAULT 'sha256_legacy',
    senha_iteracoes INTEGER NOT NULL DEFAULT 0,
    senha_versao INTEGER NOT NULL DEFAULT 1,
    auth_provider TEXT NOT NULL DEFAULT 'local',
    google_id TEXT UNIQUE,
    foto_url TEXT,
    data_cadastro TEXT
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_usuario_google_id
    ON usuario(google_id) WHERE google_id IS NOT NULL;

CREATE TABLE projeto (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    usuario_id INTEGER NOT NULL,
    nome TEXT NOT NULL,
    descricao TEXT,
    data_criacao TEXT NOT NULL,
    FOREIGN KEY (usuario_id) REFERENCES usuario(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_projeto_usuario_id ON projeto(usuario_id);
CREATE INDEX IF NOT EXISTS idx_projeto_nome ON projeto(nome);

CREATE TABLE gravacao (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    usuario_id INTEGER NOT NULL,
    projeto_id INTEGER,
    nome TEXT NOT NULL,
    caminho_arquivo TEXT NOT NULL,
    data_criacao TEXT NOT NULL,
    duracao_segundos INTEGER DEFAULT 0,
    status TEXT NOT NULL DEFAULT 'concluida'
        CHECK (status IN ('concluida', 'interrompida', 'arquivo_ausente', 'excluida')),
    tamanho_bytes INTEGER NOT NULL DEFAULT 0 CHECK (tamanho_bytes >= 0),
    formato_audio TEXT NOT NULL DEFAULT 'm4a',
    FOREIGN KEY (usuario_id) REFERENCES usuario(id) ON DELETE CASCADE,

TABELAS REMOVIDAS (existiam no TCC, não existem mais no app):
  - arquivo_audio: dados de arquivo incorporados diretamente na tabela gravacao
  - feedback: feedback é exibido visualmente sem persistência no banco
  - dashboard_indicador: indicadores calculados em tempo real sem tabela dedicada
  - historico_gravacao: renomeada e expandida para historico_acao

TABELAS ADICIONADAS (não existiam no TCC):
  - projeto: projetos musicais com FK para usuario
  - comando_personalizado: frases personalizadas do usuário
  - configuracao_app: preferências do aplicativo (singleton)

CAMPOS ADICIONADOS em tabelas existentes:
  usuario:
    + senha_salt, senha_algoritmo, senha_iteracoes, senha_versao (segurança)
    + auth_provider, google_id, foto_url (Google Sign-In)
    + data_cadastro
  gravacao:
    + status (concluida/interrompida/arquivo_ausente/excluida)
    + tamanho_bytes, formato_audio
    + projeto_id (FK para projeto)

CAMPOS RENOMEADOS em tabelas existentes:
  historico_gravacao -> historico_acao
    acao -> tipo (mesmo campo, renomeado)
    id_historico -> id
    id_usuario -> usuario_id
    id_gravacao -> gravacao_id
    + descricao agora é obrigatório
    + adicionado projeto_id

TEXTO PRONTO PARA TCC (explicação da evolução do banco):
"O banco de dados do sistema TouchLess evoluiu de forma incremental ao longo
do desenvolvimento, resultando na versão atual (versão 10 do esquema de
dados). A evolução foi realizada por meio de migrations controladas, que
adicionaram novas colunas e tabelas sem perda de dados em instalações
anteriores. As principais mudanças em relação ao modelo inicial incluem a
adição de suporte a projetos musicais, autenticação via provedor externo
Google, configurações persistentes do aplicativo, comandos personalizados
de voz e um modelo de histórico de ações mais abrangente. Tabelas do modelo
inicial que não foram implementadas (arquivo_audio, feedback,
dashboard_indicador) foram substituídas por soluções integradas às tabelas
existentes ou por processamento em tempo real, simplificando o esquema de dados."
